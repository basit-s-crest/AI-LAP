What This System Is

SafeCircle is a HIPAA-compliant, real-time clinical decision support platform. It monitors coaching/therapy sessions and patient communication channels (chat, journals, assessments) to detect early signs of emotional distress by combining text sentiment, voice acoustics, and facial expression analysis. It gives coaches live, AI-assisted risk insights during sessions and keeps a longitudinal clinical memory for each patient.

The system is built as four cooperating services: a Next.js web dashboard, a Node.js/Express API for accounts and messaging, a Python/FastAPI service for AI inference and real-time audio/video analysis, and a Redis-backed background job queue — all sitting on top of two Supabase PostgreSQL databases.

SafeCircle is built around four specialized portals, each serving a different role in the wellness ecosystem.

2.1 Super Admin Portal

Administrator overseeing the entire SafeCircle ecosystem across every organization, coach, and member. This is the command center of the platform.

FeatureWhat It Does
Platform DashboardAt-a-glance view of total registered users, active coaches, total sessions completed, and accounts pending verification, plus a live activity feed of signups, community activity, session bookings, and flagged content.
Platform Activity ChartEngagement graph toggling between 7 / 15 / 30-day views, tracking member, coach, and organization logins together to spot spikes, drops, or growth trends.
User ManagementSearchable, platform-wide table of every account (name, email, verification status, last active, organization). Admins verify pending accounts, review activity, and remove accounts that violate platform standards.

Organizations ManagementView each partner organization's type, subscription plan, active members, assigned coaches, and monthly usage. Add organizations, update billing, and monitor usage against plan limits.
Platform SettingsSystem-wide configuration: branding (name, tagline), support email address, maximum session duration, self-registration on/off, and maintenance mode.

2.3 Coach Portal

Mental health coaches, therapists, and clinicians conducting sessions and monitoring client risk.

FeatureWhat It Does
Live Session HostingHosts the video/audio coaching session via LiveKit, with camera/mic controls and session lifecycle management.
Live Session MonitorReal-time transcription of session audio, live acoustic tone analysis (pitch, energy, pause ratio), and live AI-generated clinical prompt suggestions delivered during the session.

Step-by-Step Local Setup Guide

Follow this guide to get all SafeCircle services running locally in development mode.

Prerequisites

Make sure your local machine has the following tools installed and running:

  • Node.js v22 LTS (recommended)
  • Python v3.12 (3.13+ has compatibility issues with specific package wheels)
  • PostgreSQL (version 15+ recommended, running on default port 5432)
  • Redis (running on default port 6379)
  • uv (high-performance Python package installer)

Installation of uv:

Windows (PowerShell):

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

Mac/Linux:

curl -LsSf https://astral.sh/uv/install.sh | sh

Step 1: Start Redis via Docker

SafeCircle relies on Redis for BullMQ queues and SSE live update Pub/Sub mechanisms. The most straightforward way to run Redis locally on any system is using a Docker container:

docker run -d --name safecircle-redis-local -p 6379:6379 redis:alpine

To verify that Redis is running, check the container status:

docker ps

Step 2: Create PostgreSQL Databases

You need to manually create two PostgreSQL databases in your database instance (e.g., via psql or pgAdmin):

CREATE DATABASE vasl_ts;   -- Used by the TypeScript Express backend
CREATE DATABASE vasl;      -- Used by the Python FastAPI backend

Step 3: Set Up Environment Files

Create or copy the environment configuration files from their respective examples:

  1. Frontend Client (frontend/FE/.env.local): Create this file inside the frontend/FE/ folder (copied from .env.example).
  2. TypeScript Backend (frontend/BE/.env): Create this file inside the frontend/BE/ folder.
  3. Python Backend (backend/.env): Create this file inside the backend/ folder.

(Refer to the environment configuration templates in Section 4 of the Markdown guide).

Step 4: Install JavaScript Workspace Dependencies

From the project root directory, run:

npm install --force

This command hoists and installs all npm dependencies for both frontend/FE and frontend/BE workspaces at the root level.

Step 5: Setup TypeScript Express Backend & Database

Navigate to the Express backend directory, generate the Prisma client, and run database migrations to deploy schemas to vasl_ts:

cd frontend/BE
npx prisma generate
npx prisma migrate deploy

Step 6: Setup Python FastAPI Backend

Navigate to the Python backend directory, initialize and activate the virtual environment, install dependencies, and run database migrations to populate vasl:

cd backend
uv venv --python 3.12

# Windows (PowerShell):
.venv\Scripts\activate

# Mac / Linux:
source .venv/bin/activate

# Install dependencies:
uv pip install -r requirements.txt

# Run migrations:
python -m app.migrate

Step 7: Start All Services

Option A: Windows Automated Launch (Recommended)

From the project root directory, run the PowerShell script to spin up all 4 services concurrently in separate windows:

.\dev.ps1

Option B: Manual Terminal Startup (4 terminals)

Open 4 separate terminal tabs from the project root directory and run:

  • Terminal 1: Next.js Frontend (runs at http://localhost:3000) 
    cd frontend/FE
npm run dev
  • Terminal 2: BullMQ Background Worker (feeds jobs to Python API) 
    cd frontend/FE
npm run worker
  • Terminal 3: TypeScript Express Backend (runs at http://localhost:4000) 
    cd frontend/BE
npm run dev
  • Terminal 4: Python FastAPI Backend (runs at http://localhost:8001) 
    cd backend
# Activate venv: Windows: .venv\Scripts\activate | Mac/Linux: source .venv/bin/activate
uvicorn main:app --host 0.0.0.0 --reload --loop asyncio --port 8001

Step-by-Step Docker Setup Guide

This project is configured with a multi-container Docker Compose setup to run all SafeCircle services under a single command by pulling pre-built images from Docker Hub.

Prerequisites

  • Docker and Docker Compose installed on your host system.
  • A running PostgreSQL database (e.g., a remote Supabase instance or a local Docker/host database instance).

Step 1: Copy the Docker Environment Template

When running the SafeCircle stack by pulling pre-built Docker images under the basit0crest Docker Hub namespace (configured in docker-compose.yml), you must manage a single consolidated .env file in the project root. This file merges all environment variables required by all containers.

Copy the Docker-specific environment template to the project root:

Windows (PowerShell):

Copy-Item .env.docker.example .env

Mac/Linux:

cp .env.docker.example .env

Open the root .env file and configure your database URLs and API keys (such as OPENROUTER_API_KEY, DEEPGRAM_API_KEY, etc.).

Note on Network Mapping: Environment variables prefixed with NEXT_PUBLIC_ are resolved in the user's browser, so they must point to localhost (e.g., http://localhost:4000). Other variables used internally by Docker containers (like FASTAPI_URL and REDIS_URL) use the container hostnames (e.g., http://python:8001 or redis://redis:6379/0).

Step 2: Deploy Database Migrations

Before launching the docker-compose stack, ensure your databases are migrated:

  1. TypeScript Express Backend Schema (vasl_ts): Deploy the schema from your host computer using Prisma (ensure your local frontend/BE/.env matches your target database credentials): 
    cd frontend/BE
npx prisma migrate deploy
  2. Python FastAPI Backend Schema (vasl): Once the containers are running (Step 3), deploy migrations inside the running container: 
    docker compose exec python python -m app.migrate

Step 3: Run the Docker Compose Stack

From the project root directory, launch all services in detached mode:

docker compose up -d

This command starts 5 containers:

  • safecircle-redis on port 6379
  • safecircle-python on port 8001
  • safecircle-backend on port 4000
  • safecircle-frontend on port 3000
  • safecircle-worker (BullMQ background worker)

Step 4: Verify and Monitor Containers

Verify that the containers are running and healthy:

docker compose ps

To monitor logs for all containers in real time:

docker compose logs -f

Or view logs for a specific service (e.g., the Python backend):

docker compose logs -f python

Step 5: Stop the Containers

To stop and clean up the container stack: 

docker compose down
